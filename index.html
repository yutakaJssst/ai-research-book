第7章データ分析と可視化

Titanicデータを使った本文数値の検証と、掲載図の再生成に使うコードを配布します。

スライド・配布ファイル

データ分析スライド 数値検証コード 図生成コード

Titanicデータ分析ノートブック

データの取得から欠損値確認、可視化、分類モデルの評価まで、上から順に実行できます。末尾では数値検証コードと図生成コードも試せます。

Colabで開く ノートブックを保存 準備と実行手順

  1. 「Colabで開く」からノートブックを開きます。実行にはGoogleアカウントへのログインが必要です。編集した内容を残す場合は、「ファイル」から「ドライブにコピーを保存」を選びます。
  2. 上から順にセルを実行すると、必要なライブラリを準備し、Kaggleの公開データ（版1）を取得します。本の train.csv と891行・12列の全値が一致することを確認しています。データ本体は本サイトには置いていません。
  3. 補完値を決める前に訓練用と評価用へ分ける順序を確認してください。
  4. 結果を本文の数値と照合します。検証環境とデータの確認方法はノートブック内に記載しています。
  5. 保存前に実行環境を再起動し、すべてのコードセルを上から順に再実行します。実行環境が削除された場合も、先頭から実行すればデータを再取得できます。

自動取得ができない場合は、Kaggleのコンペティションページで利用条件を確認して取得した train.csv をアップロードしてください。すでにファイルがあれば、そのデータを使います。

信頼区間とSafeComp事例の検算

掲載図の生存率の95％信頼区間はWilson法で計算します。各乗客の生死を独立な試行とみなす二項モデルに基づき、区間は0〜1に収まります。群間差の検定結果を示すものではありません。

情報メモとGitHub Pagesの公開手順

本文で説明するHTMLの骨格です。完成した研究紹介ページではなく、各セクションに自分の情報やリンク、スタイルを書き加えていく出発点です。

HTMLを保存する 表示を見る

  1. GitHub Desktopで新しいリポジトリを作り、名前を 自分のGitHubユーザ名.github.io にします。そのリポジトリのフォルダをVS Codeで開きます。
  2. 取得したHTML、またはAIが生成したコードを index.html として保存します。
  3. まずブラウザでファイルを開いて表示を確認します。VS CodeのLive Serverを使うと、編集しながらプレビューできます。
  4. コードと表示を見比べ、名前、所属、研究内容やリンクを公開してよい情報で書き加えます（AIに各セクションの記述やスタイルを補ってもらってもかまいません）。一度に1箇所ずつ変更し、その都度表示とリンクを確認します。
  5. 公開前チェックを済ませ、変更差分を確認してコミットします。GitHub Pagesへの公開後は、別の端末やシークレットウィンドウからも確認します。

本文の演習では、ユーザサイトとして https://ユーザ名.github.io/ に公開します。GitHub Freeで行う場合は、公開してよいファイルだけを入れ、初回の Publish Repository で Keep this code private を外します。GitHubの Settings → Pages で Deploy from a branch、main、/(root) を選び、公開URLを確認してください。

別名のリポジトリで作るプロジェクトサイトは、通常 https://ユーザ名.github.io/リポジトリ名/ になります。組織の規程で公開できない場合は、非公開リポジトリとローカルプレビューを使い、公開しない理由を記録します。詳しい操作は画面例付きの公開手順を参照してください。
