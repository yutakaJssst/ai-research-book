# 第9章：発表準備とピアレビュー

2026年10月25日改訂の原稿に対応。
研究が途中でも、現時点で分かったことと、まだ分からないことを説明してください。
公開・共有してよい情報だけを記入します。

## 発表前に整理する

- 研究テーマと背景：
- 解決したい課題：
- 分かったことと根拠となる成果物：
- AIに任せた作業と、出力を確かめた方法：
- AIが役立った点：
- AIでは不十分だった点と、自分で行った判断：
- 残された課題と今後の方針：

## 3分発表の配分例

| スライド | 内容 | 時間目安 |
|---|---|---|
| 1 | タイトル、自己紹介 | 10秒 |
| 2 | 研究テーマの紹介 | 20秒 |
| 3 | 研究で分かったことと根拠となる成果物 | 1分 |
| 4 | AIを使った作業、検証方法、効果と限界 | 1分 |
| 5 | まとめ、今後の展望 | 30秒 |

発表3分、質疑応答2分を目安にします。
声に出して時間を測り、超える場合は伝える内容を絞ってください。
AIに原稿の圧縮を依頼したときも、研究の成果と根拠、検証方法が落ちていないかを自分で確かめます。

## ピアレビューの記入欄

発表テーマ：

| 観点 | 確認すること | コメント |
|---|---|---|
| 研究内容 | 背景、目的、方法、結果が分かるか | |
| 新規性 | 既存研究との差分が説明されているか | |
| AI活用 | 使った場面と検証方法が具体的か | |
| 倫理と公開範囲 | 機密情報や個人情報への配慮があるか | |
| 発表資料 | 1枚1メッセージで、話とスライドが対応しているか | |
| 今後の方針 | AIに任せる部分と自分で判断する部分が明確か | |

必要に応じて各観点を5点満点で採点してもよいですが、点数だけで終わらずコメントを添えてください。

- 良かった点を1つ：
- 改善点を1つ（場所、理由、直し方）：

記入例：「3枚目のグラフは、縦軸の単位が口頭でしか説明されなかったので、軸ラベルに単位を書くと初見でも分かると思います。」

## コメントを受け取ったら

| 指摘 | 対応（すぐ直す／検討する／採用しない） | 理由と次の作業 |
|---|---|---|
| | | |

すべての指摘に従う必要はありません。
AIに分類を手伝わせた場合も、優先度と採否は自分で決めます。

## AI活用を振り返る

第2章のAI活用記録票も参照し、効果、限界、自分の判断、今後の改善を書き出します。
次の例は、自分の経験を思い出すためのものです。

| 項目 | 記入例 | 自分の経験 |
|---|---|---|
| 効果があった場面 | キーワード拡張、Abstractの短文化、グラフコード作成 | |
| 限界があった場面 | 文献情報の誤り、統計手法の前提確認、研究固有の判断 | |
| 自分で判断したこと | 採用する文献、主張の強さ、公開範囲、分析結果の解釈 | |
| 今後の改善 | 検証手順を先に決める、AI対話ログを整理する、プロンプトを共有する | |

効果を述べるときは、比較した作業時間や修正前後の成果物など、判断の根拠も添えてください。
未確認の点は、AI活用記録票の「確認結果」に残します。

本文の数学の例については、[AIによる数学の原稿と形式検証](https://yutakajssst.github.io/ai-research-book/guides/ai-math.html)に、件数と訂正履歴、公式資料へのリンクを掲載しています。
確認日を添えた記録なので、その後の変更はリンク先の公式資料で確認してください。

## 教員向け：検証記録の評価例

第2章のAI活用記録票を使い、成果物だけでなく、何を確かめて採否を決めたかを評価します。
下表は、ピアレビューの「AI活用」の観点を5点満点で採点する場合の例です。
2点・4点は隣り合う段階の間として扱い、課題に応じて必要な確認範囲を先に伝えてください。

| 点数の目安 | 記録で確認できること |
|---|---|
| 1点 | 使用したAIや出力は示されているが、「確認した」という記述だけで、照合した資料や結果が分からない |
| 3点 | 根拠資料や実行結果を示して出力を確認しているが、確認の範囲や採否の理由が十分に説明されていない |
| 5点 | 作業の目的に合う方法で確認し、根拠箇所や実行結果、確認できた範囲、採否の理由を具体的に説明している |

研究の結果自体がよいか、発表が分かりやすいかは、他の観点で評価します。
AIが出した文章をどれだけ書き直したか、誤りを何件見つけたかだけでは評価しません。
確認して問題がなければ、そのまま採用した判断も評価します。
確認できずに保留した場合も、何が不明で、次に何を確認するかを説明できているか見てください。

### 説明用の記録例

次は実在の学生の提出物ではなく、記録の違いを示すための例です。

- 「AIが作った平均値関数を確認した。問題なかった」だけでは、何を確かめたか分かりません。
- 「入力 `[2, 4, 6]` の期待値を手計算で4と求め、実行結果も4だった」とあれば、確認した入力と根拠が分かります。
- そこに「この確認は通常の入力1件だけであり、空の入力や1件だけの入力は未確認なので、研究に使う前に追加する」とあれば、確認範囲と次の判断も分かります。

AI回答と、その回答をどう扱ったかを一緒に提出させる考え方は、伊藤貴之『生成AIを活用したレポート・論文の書き方』（慶應義塾大学出版会、2026年）第2章・図2.5を参考にしています。
本シートでは、修正の有無より、確認結果と採否の根拠を重視しています。
